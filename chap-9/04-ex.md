
## 4. Quel est le nombre de comparaisons nécessaires au tri rapide pour traiter un fichier de N éléments égaux ?


A chaque utilisation de partitionner dans le tri, nous executons le code ci-dessous :

```
int pivot = tab[r];
while(1)
{
    while(tab[++i]<pivot);
    while(tab[--j]>pivot);
    if(i>=j) break;
    q = tab[i];
    tab[i] = tab[j];
    tab[j] = q;
}
q = tab[i];
tab[i] = tab[r];
tab[r] = q;
```

Puisque tous les éléments sont égaux, les pointeurs i et j ne progresse que d'une case et s'arretent.
il y a donc 2 comparaisons (une pour i et une pour j) et on recommence jusqu'a ce que i = j.
Cette égalité se produit donc lorsque i == r+l /2.

Le partionnement dans ce cas est donc optimal pusiqu'il coupe le fichier en 2 sous-parties égales (ou presque compte tenu
de la division entière.

Il y aura donc N comparaisons.

Puisque nous sommes au milieu du fichier à chaque fois, il y aura donc LgN partionnement.

Ainsi, nous sommes dans le cas optimal : $$N lg N$$.
